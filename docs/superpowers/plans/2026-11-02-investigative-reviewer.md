# Native Investigative Reviewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run an investigative reviewer through the installed standalone OMP CLI and managed Herdr/tmux, with normal tools, reproducible follow-up evidence, isolated test workspaces and existing durable review outcomes.

**Architecture:** Keep Python admission, packet selection, report/proposal validation, dedup and finalization. Replace only SDK dispatch with a one-shot managed OMP process and a small reviewer-role extension/skill. Add run-scoped supplementary evidence and Treehouse probe leases, not a general agent framework or fake worker task.

**Tech Stack:** Existing Python 3.12+, standalone OMP >=18.14.0, Herdr/tmux and Treehouse; native OMP extension APIs. No importable OMP SDK, Bun host, MCP server, or new Python dependency is required for reviewer execution.

**Spec:** `docs/superpowers/specs/2026-11-02-investigative-reviewer-design.md`

## Global Constraints

- Preserve `agd --home . reviewer run`, manual/timer admission, immutable history, final-response seed selection, pending-proof coverage, retained-only dedup, reviewer-self exclusion and inert proposals.
- Config schema 2 keeps schedule/review_model and max_candidates=20, max_input_bytes=262144, max_output_bytes=65536, max_runtime_seconds=1800; remove max_model_calls/provider-inflight accounting, not historical snapshots.
- Execute normal OMP with `--print --mode json --no-extensions --skills agd-reviewer --cwd RUN_DIRECTORY --session-dir REVIEWER_SESSION_DIR -e lib/omp-reviewer.ts --max-time REMAINING`; add `--model` only for an explicit reviewer selector. Do not pass `--no-tools` or mutate model/auth configuration.
- Success requires a proved child exit 0, owned endpoint/process absence, a valid bounded report file and existing durable finalization; never Herdr idle or terminal prose.
- Investigation remains recommendation-only policy, not an OS sandbox. No automatic remediation, publication, service/configuration changes, installs, or proposal application.
- Project execution only in run-owned Treehouse probe leases; dirty/uncertain work is retained, not reset/cleaned/discarded.
- Langfuse CLI and telemetry remain optional; no implicit cloud, tool download or Docker start during review.
- Fresh process activation is required for changed extensions; no promise of live extension hot reload.

## Review Focus

- Report-looking output followed by nonzero exit/timeout must not commit proposals or consume seed coverage: Task 1 runner tests.
- A timer with minimal environment and no active central must launch only its owned backend, never the default/focused Herdr session: Task 2 backend/timer tests.
- Supplementary evidence from another run or an unsafe file must not become valid citations: Task 3 evidence tests.
- Interrupted Treehouse allocation, dirty probes and surviving delegated processes must never produce duplicate leases or destructive cleanup: Task 4 workspace tests.
- Old schema-1 config/receipts and disabled timers must retain meaning through upgrade; no stale SDK unit may be silently re-enabled: Task 5 migration tests.

## Self-review / handoff criteria

Every user requirement maps to a task: normal managed CLI/tools and report durability (1–2), further evidence and Langfuse investigation instructions (3; optional environment from Plan A), isolated code/test execution (4), compatibility/schedules/cleanup/real proof (5). No requirement is reduced to a prompt-only safety guarantee or mocked output. Exact provider-stream accounting is deliberately removed; provenance, data-loss prevention and authority rules are not.

Review both plans and the shared spec before execution. No product implementation, package installation, provider call, live restart, push/PR or landing has occurred as part of writing this plan.
