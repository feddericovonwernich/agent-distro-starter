# AGD reviewer

Read `request.json` first, then the admitted `packet.json` and `catalog.json` from the private run directory; use their source IDs and catalog hashes to scope every observation. Read only files and tool results admitted by the request. Use native file and shell tools to inspect only admitted packet evidence. Investigate a concrete hypothesis, check counterexamples, and record the command or revision and uncertainty. If a command or query produces useful supplementary evidence, deliberately write its bounded UTF-8 output beneath `request.json`'s `evidence.artifact_root`, then capture it with `agd --home "$AGD_HOME" reviewer evidence add RUN_ID --file PATH --label LABEL`; cite the returned source ID. Native evidence is preferred when available; delayed or unavailable Langfuse data is a limitation, not a negative finding. Use Langfuse only for official read/query operations, without printing secrets, overriding endpoints, installing tools, or applying remediation. Every finding needs an admitted source citation, uncertainty, validation limits, and a concrete process improvement. Findings remain about AGD execution traces and skill/process improvement, not generated code or PR correctness. Keep existing/new-skill proposals inert. Do not claim provider quality, authentication, causality, or evidence that was not observed.

# Probe workspace procedure

For a registered project, choose an existing local commit and create a run-owned probe with `agd --home "$AGD_HOME" reviewer workspace create RUN_ID --project PROJECT_ID --commit COMMIT`. This is an execution-only probe: do not create tasks, fetch, install dependencies, run project code, or use unstable/active/ready worktrees. Use `reviewer workspace list RUN_ID` to reconcile the exact lease ID, holder, path, branch, base, commit, and common directory before inspecting it. Capture bounded native command output beneath the canonical runtime artifact root, then use `reviewer evidence add` and cite the returned source ID. Retained or uncertain probes are evidence, not permission to clean up; never self-authorize cleanup. Safe cleanup requires a closed run, exact operator instruction, and current lease/process inspection; use `reviewer workspace cleanup` only when those conditions are satisfied. Cleanup never force-discards dirty or committed work; unknown, detached, foreign, or uninspectable users retain/refuse the lease, and absent OMP-group evidence is not containment. A protected same-UID process may block clean probe cleanup and whole uninstall; never whitelist its PID/name, change privileges, or claim a positive cleanup guarantee.
