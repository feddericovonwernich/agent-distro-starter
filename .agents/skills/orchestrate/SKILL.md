# Worker orchestration

Create each task with its immutable harness and skill selection, then launch it with the chosen backend. The live-verified combinations use `bin/agd task create ID ... --harness omp` followed by `bin/agd worker launch ID --backend tmux|herdr`; Herdr additionally needs `AGD_HERDR_SESSION` set to an explicit non-default named server from inside a managed pane. Inspect `docs/compatibility.md` before choosing Cursor. `--unattended` requires a separate `task approve ID --action unattended --target ID --instruction FILE` and the returned approval ID. Do not grant a tool permission or bypass a prompt merely because a worker requests it. OMP workers run in their leased worktrees with their own extension; the central owns the watcher.

Use `worker skills list` and `worker profiles list` before task creation. `task create` may use the default profile, an explicit `--profile`, `--skill-mode curated --skill` choices, or explicit `--skill-mode none`; profiles and curated choices never combine. Selected OMP skills are frozen and materialized into task-owned ignored paths before `prepared`. Launch and relaunch use only that snapshot. Cursor nonempty skill selections refuse until authenticated native discovery is verified; an empty selection preserves the existing Cursor compatibility path.

`worker inspect ID` reports endpoint evidence. `worker send ID --file FILE` atomically queues a steering message; `worker inbox ID` shows pending messages until that incarnation acknowledges them. Queued or submitted does not mean processed. `session status`, `events list`, and `task status ID` show watcher health, wakes and open decisions. Handle a wake, then `events acknowledge EVENT_ID` with exact IDs. To answer a named decision after obtaining the user's answer, `decision resolve ID KEY --answer FILE` persists it and queues it for the worker; acknowledgement alone never resolves it.

`worker interrupt ID` sends Escape only on a native busy OMP turn; inspect again rather than assuming the process ended. `worker stop ID` needs native idle evidence and verifies exit and pane absence before reporting success. `worker relaunch ID` requires positive previous-process and endpoint absence and reuses its exact workspace; unresolved state must remain for inspection. On watcher restart use `session reconcile`, inspect pending events/leases, and do not allocate a replacement task or kill unknown endpoints. Never use the focused or default Herdr session as an implicit fallback; a stopped/replaced named server makes endpoint identity unknown. Cursor Agent requires user authentication and live transcript binding before operational claims.
